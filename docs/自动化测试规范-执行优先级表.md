# 自动化测试规范-执行优先级表

> 配套《自动化测试规范总纲.md》使用。本表回答两个问题：**先做什么、用什么手段做**。
> 原则：**ROI 分层**——数据走接口测试、交互走静态审查、流程只跑 P0 冒烟。不要追求"全部自动化"。

---

## 1. 执行优先级总览（按 ROI 排序）

| 层级 | 做什么 | 手段 | 频率 | 成本 | 收益 |
|------|--------|------|------|------|------|
| **S0 数据正确性** | 金额/状态/幂等/并发/权限/安全 | 接口/单元测试（JUnit/Supertest） | 每次 push | 低中 | 极高（业务核心） |
| **S1 交互静态审查** | 控件选型/表单校验/安全写法 | AI 代码审查（读代码） | 每次 push | 低 | 高（防用错控件） |
| **S2 核心流程冒烟** | 登录→主操作→提交/支付 | E2E 自动化（Playwright/automator） | 每次发版 | 中 | 高（防主流程断） |
| **S3 发版前抽查** | P1 级交互/体验 | 自动化抽查 + 人工抽测 | 发版前 | 中高 | 中 |
| **S4 体验迭代** | P2 级（无障碍/动效/兼容） | 人工/按里程碑 | 按迭代 | 低 | 低（锦上添花） |

> 执行顺序：S0 → S1 立即可开始；S2 在测试环境就绪后；S3/S4 视资源逐步加。

---

## 2. S0 数据正确性（先做，ROI 最高）

**目标**：业务数据算得对、存得对、权限对、安全对。

| 覆盖范围 | 编号段 | 落地建议 |
|---------|--------|---------|
| 计算正确性 | D-0201~0219 | 优先：金额精度、折扣、汇总、百分比、舍入、幂等、余额流水 |
| 一致性 | D-0101~0112 | 事务原子、缓存一致、状态同步、异步最终一致 |
| 边界异常 | D-0301~0317 | 空值/极值/非法值/重复值/溢出/分页边界 |
| 并发 | D-0701~0714 | 并发下单/扣款/支付回调/消息幂等/并发注册 |
| 权限 | D-0501~0513 | 越权读/改/删、字段级权限、租户隔离、权限矩阵 |
| 安全 | D-0601~0616 | 明文/传输/注入/XSS/CSRF/上传安全/Token |
| 时间 | D-0801~0813 | 只做 P1 部分（时区、格式、跨天），P2 缓 |

**手段**：
- 后端：Spring Boot 项目加 JUnit + MockMvc，每个核心 Service/Controller 一个测试类
- 接口层：Supertest/Postman 集合，断言状态码 + 返回体 + 关键业务字段
- 幂等/并发：并发线程模拟（同参数并发请求只成功一次）

**示例断言（金额精度）**：
```java
assertEquals(0, BigDecimal.valueOf(0.1).add(BigDecimal.valueOf(0.2))
    .compareTo(BigDecimal.valueOf(0.3)));
```

**入口**：每次 push 自动跑（接入现有 `publish-test-report.sh` 链路）。

---

## 3. S1 交互静态审查（次优先，成本最低）

**目标**：用 AI 读代码，提前拦下"用错控件/漏校验/不安全写法"。

| 覆盖范围 | 编号段 | AI 检查什么 |
|---------|--------|------------|
| 控件选型 | UI-01xx/02xx | 日期/地址/枚举/上传是否用了类型化控件，禁止 input 手填 |
| 表单校验 | UI-04xx | 必填/格式/长度/交叉校验是否实现，错误定位是否做 |
| 安全写法 | UI-0419、UI-1508 | XSS 转义、富文本 v-html 裸渲染 |
| 按钮反馈 | UI-03xx | 危险操作二次确认、提交 loading、空/错/成功态 |
| 可访问性基础 | UI-1211 | 输入是否有 label 关联 |

**手段**：
- 接进现有 `ai-code-review.sh`，新增"UI 规范"审查规则集
- 每次 push 扫描 diff，输出：违反编号 + 文件行号 + 修正建议
- 只报 P0/P1 条目（P2 仅提示不阻断）

**关键认知**：这一层不需要起测试环境，成本趋近于零，但能拦住 80% 的交互规范问题。

---

## 4. S2 核心流程冒烟（测试环境就绪后做）

**目标**：主流程不断。

| 核心链路 | 对应编号 | 手段 |
|---------|---------|------|
| 登录/注册/退出 | F-03xx | Playwright（Web）/ miniprogram-automator（小程序） |
| 主操作（生成/提交） | F-07xx、F-0801 | E2E：造数→操作→断言结果 |
| 支付全链路 | F-0801~0811 | E2E + 接口层回调模拟 |
| 列表/详情 | F-05xx、F-06xx | E2E 只做首页加载 + 首条详情 |

**落地建议**：
- 只做 3~5 条核心链路脚本，不做全量 UI 自动化
- 用例数据自建自清（F-1303/F-1304）
- 失败必须截图留证（F-1305）

---

## 5. S3 发版前抽查（P1 级）

**目标**：P1 交互与体验在发版前确认。

| 检查项 | 手段 |
|--------|------|
| 表单校验生效（UI-0401~0422） | 自动化抽查 3~5 个关键表单 + 人工兜底 |
| 权限控制生效（UI-08xx、D-05xx） | 自动化：未登录/无权限访问受限页 |
| 弱网/断网提示（UI-10xx） | 人工抽测（DevTools 降速） |
| 滚动/遮挡（UI-05xx） | 人工抽测关键长页面 |
| 数据脱敏（D-0608） | AI 审查 + 接口抽查 |

**手段**：不单独建自动化，融入 S2 脚本 + 发版前人工 checklist（总纲 4.2）。

---

## 6. S4 体验迭代（P2，不设硬门槛）

| 覆盖范围 | 说明 |
|---------|------|
| 无障碍 UI-12xx | 无合规要求时可推迟，只做 label 关联（UI-1211） |
| 动效 UI-13xx | 只保留超时兜底（UI-1309）、状态切换刷新（UI-1313）两条 P0 |
| 兼容性 UI-11xx | 按目标用户设备定最低版本，不无限铺开 |
| 国际化 F-14xx | 无海外市场直接跳过 |

| 形态 | S0 | S1 | S2 | S3 | S4 |

## 9. 关键纪律（防止 ROI 被稀释）

1. **不追求全自动化**：交互细节靠 AI 静态审查 + 人工抽测，不要为每条 UI 规则写 E2E。
2. **P0 才阻断**：只有 P0 失败阻断发布；P1/P2 走缺陷流程，不卡发布。
3. **新增功能必带测试**：S0 接口断言或 S1 审查规则二选一必须覆盖（F-1307）。
4. **测试数据独立自清**：禁止共享/生产数据，禁止跑后留脏数据。
5. **flaky 不允许上线**：偶发失败的用例要修或删，不要带病跑（F-1302）。
6. **按端裁剪**：每季度随产品形态调整一次标签裁剪。
7. **本地化 TDD 纪律（Ti / Hermes 落地）**：当前阶段暂不 push，但每完成一个功能仍必须产出「改动说明（docs/changelogs/）+ 测试脚本」，按《自动化测试脚本交付与执行规范》生成并本地跑通；先写/同步更新测试（S0 或 S1）再落代码，保持代码 / 记录 / 脚本同版本对齐。
