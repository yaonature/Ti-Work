# Ti 系列"工作方式蒸馏" 云端蒸馏与下发验证链路 研发实施蓝图

> 状态：研发实施蓝图（2026-09-09 定稿草案，**云端侧**，待评审后分期实施）。
>
> 口径对齐（与《设计评审稿》同一轮收敛，2026-09-09）：
> - **共创两层模型**：L1 个人本地养成全员可用（桌面 D6，与本链路无数据往来）；L2 共创沉淀通道默认关闭、账号级 Gate、云端定向开通共创账号后自动采集；
> - **分层验证制**：共创准入 = 可验证的专业性（执业资质 + L2 度量 + 修订链稀疏 + 同行背书），共创进候选池，商业化价值由资产验收决定；
> - **云端无执行、无沙箱**：云端只做"收口 → 加工 → 治理 → 验证编排 → 分发"，执行永远发生在被下发账号的**本机真机**；验证动作 = **管理员把预沉淀版本（candidate）下发到指定账号本机真机试跑**，云端收反馈回流迭代；
> - **同一下发管道**：预沉淀内测（管理员名单）与正式权益制下发共用管道，仅授权策略不同；
> - **服务载体分层（2026-09-09 定稿，方案 A）**：本链路"云端业务承载"指 **Ti Work 配套云端管理端**——与 Ti Work 桌面**同账号同源**的产品 Web 云（暂名，本链路主载体），承载共创运营 / 资产沉淀 / 加工业务 / 下发验证；**Ti Mind（LingShu）仅为能力供给底座**（模型 / 蒸馏算法 / 知识抽取）；**OPC 仅为平台治理关卡**（商业化审核 / 支付与权益发令 / 不可变审计）；桌面（Hermes-Studio）为执行与真机试跑端。参见《设计评审稿》命名口径。
> - 上下游衔接：本链路上游 = 桌面《素材采集链路 研发实施蓝图》D1-D5（共创账号自动回传脱敏契约样本）；下游 = 桌面 Skill 加载器（接收预沉淀/正式版本、本机试跑与使用）。

## 1. 范围与定位

**本链路做什么**：把共创账号回流样本加工成可交付的 Skill 规范资产，并支撑"验证 → 审核 → 分发"全链路的云端功能实现。

**本链路不做什么**（边界，避免与既有定稿冲突）：
- 不承担任务执行，不建云端沙箱——执行与真实验收永远在桌面真机；
- 不持有真实交付正文——只收脱敏契约样本（D1-D5 口径：需求语义摘要、交付物规范要素、修订链 diff、脱敏快照引用）；
- 不触碰普通账号的本地资产（L1 数据不出本机）。

**服务载体（2026-09-09 定稿，方案 A 分层）**：
- **Ti Work 配套云端管理端（本链路主载体；与桌面同账号同源的产品 Web 云，暂名）**：承载共创账号运营（C1）、样本收口与资产库（C2）、蒸馏加工业务（C3 引擎本体）、下发名单与试跑回流治理（C4）、正式分发执行（C5 下发侧）——资产与业务数据沉淀于此，随桌面产品共同演进；
- **Ti Mind（LingShu）**：仅作能力供给底座——C3 加工调用其模型 / 蒸馏聚类 / 知识抽取能力，C7 复用其平台横切服务；不持有资产与业务状态；
- **OPC**：仅作平台治理关卡——C6 商业化审核（涉密巡检 / 发布审批，admin 后台打审核戳）、C5 支付与权益真相收口、平台级不可变审计；
- **Hermes-Studio（桌面端）**：采集回传、真机试跑、正式资产本机加载运行；仅作为契约消费端做最小配合（见 §8）。

本链路**不在 Hermes-Studio（桌面端）仓库内实施**（执行端只配合客户端能力）。

**分期原则**：首案最小闭环先行，以"手动/简化形态"跑通一条资产；拒绝为不存在的规模预付基建（常驻 job、计费、沙箱等一律后置）。

## 2. 端到端流程

```
共创账号（云端分层验证开通，Gate）
   │ 桌面 D1-D5 自动采集回传（脱敏契约样本）
   ▼
C2 样本收口与资产库 ──► C3 蒸馏加工引擎 ──► 预沉淀版本 candidate vN
                                                │  C4 管理员下发名单（共创者/中立验收/种子体验）
                                                ▼
                                          被下发账号本机真机试跑（云端不执行）
                                                │ 跑测记录与反馈回流
                                                ▼
                              判定通过 ──► C6 OPC 审核 ──► C5 权益制分发（正式）
                              需调整 ────► 迭代 vN+1，重入 C3/C4
```

C1（共创账号管理）横切于全流程；C7（账号/审计/任务/通知等横切服务）为底座。

**各环节落点端（对应 §1 分层）**：
- 桌面（Hermes-Studio）：D1-D5 采集回传、指定账号本机真机试跑、正式资产加载运行；
- Ti Work 云端管理端：共创 Gate 运营、样本收口库、蒸馏加工（调用 Ti Mind 能力）、candidate 版本与下发名单、反馈聚合、正式分发执行；
- OPC（admin 治理）：③ 版本审核关卡、④ 权益发令与支付真相；
- Ti Mind：能力供给（模型 / 蒸馏 / 知识抽取），不承载业务。

## 3. 功能模块拆解

### C1 共创账号管理与资质档案（Gate）
**落点端**：Ti Work 云端管理端（管理员运营面，资质判定与证据留存于此）。
- 职责：执行"分层验证制"准入、维护共创账号生命周期、向桌面同步授权状态。
- 关键实现：
  - 资质档案：执业资质核验结果、样本质量打分、修订链稀疏统计、权威同行背书记录（逐项留证据，见 §8 未决"判据实操口径"）；
  - 生命周期：开通 → 有效 → 吊销（吊销后桌面侧采集立即失效，含离线宽限策略）；
  - 状态同步：经 6.6.11-U 网络登录改造批的账号通道下发至桌面（首案过渡 = 桌面本地配置模拟，见 §8）。
- 首案取舍：手动开通/吊销即可，不做自动邀请与打分流水线。

### C2 样本收口与资产库
**落点端**：Ti Work 云端管理端（资产与样本本体沉淀地）。
- 职责：接收桌面回传的 D1-D5 契约样本，入库并提供给蒸馏加工。
- 关键实现：
  - 契约版本：与桌面契约 schema 对齐（需求摘要 ≤240 字、交付物规范要素、修订链 diff 摘要、脱敏快照引用）；
  - 存储与访问：正文一律不落明文——规范要素可检索、正文不可读；密文存储 + 最小权限访问；
  - 元数据索引：业务线、任务类别、共创账号、时间、资产版本归属（供 C3 取族、C6 巡检）；
  - 删除权：共创者/账号吊销或用户行使删除权时即时生效（对齐评审稿 §4 隐私边界）。
- 首案取舍：单库单表级简单实现，不做湖仓分层。

### C3 蒸馏加工引擎（本链路核心）
**落点端**：引擎业务功能 = Ti Work 云端管理端；加工执行时**调用 Ti Mind 供给的智能能力**（模型 / 蒸馏聚类 / 知识抽取）——Ti Mind 不持有样本与资产、不拥有加工业务状态。
加工动作（对同一"任务族"的样本族作业）：

1. **业务线 / 任务族识别**：对回流样本做语义聚类 → 归类到业务线与交付物类型（首案锚定非诉五类候选之一），形成同类样本族；
2. **L1 共性提炼（规范草案）**：族内样本对比 → 提取共有的工序骨架、模板结构、生成约束 → 产出规范草案（首案允许"蒸馏引擎辅助差分提示 + 人工起草初版规范"，L1 算法不强求一步到位）；
3. **L2 校验规则学习（差异化核心）**：吃**本人修订链**（本方案独有、Loomy/LawClaw 未收口的质量信号）——统计"本人对该类交付总在改什么"→ 反推生成约束缺陷 → 生成/补强校验规则集；这是"与本人交付一致"从人工经验变成机器规则的关键一步；
4. **KB 引用源治理**：空白范本 / 律所模板 / 法规案例引用源的授权与脱敏入库，与资产版本做引用关联（随 Skill 下发引用）；
5. **资产打包器**：工序指令 + L1 生成约束 + L2 校验规则 + KB 引用清单 → 组装为**版本化 Skill 规范资产包（candidate vN）**；
6. **调度形态**：首案 = 样本攒批 + 管理员手动触发蒸馏；规模化 = 常驻蒸馏 job（新样本自动入族、增量重提、增量回归）。

### C4 预沉淀版本治理与下发验证（内测线）
**落点端**：Ti Work 云端管理端（管理员在此维护下发名单、聚合反馈）。
- 职责：管理 candidate 版本生命周期，承载"管理员下发 → 指定账号本机试跑 → 反馈迭代"。
- 关键实现：
  - **版本状态机**：`candidate(预沉淀) → 内测 → 正式`（正式见 C5；"正式"前必须经 OPC 审核）；
  - **下发 = 管理员配置动作**：管理员维护下发名单（共创者本人 / 中立验收账号 / 种子体验账号），名单即"谁能体验 / 谁先验证"的控制面——验证者与共创者可分离，出厂证据不再只是作者自证；
  - **反馈回流契约**：收被下发账号的跑测记录（见 §4 契约字段）与问题描述 → 聚合为"迭代建议"供管理员决策（发 vN+1 或判定通过）；
  - **试跑轻量记录**：样例清单 / 版本号 / 结论的最小字段，作为将来商业化证据的最小单位，不引入重流程。
- 首案取舍：名单手动维护；不建复杂复核流（试点期由管理员 + 权威第二人人工把关，可留痕不建系统）。

### C5 商业化分发（正式线）
**落点端**：权益真相（支付 / 权益包 / 吊销发令）= OPC；下发执行 = Ti Work 云端管理端 + 桌面账号通道。
- 职责：正式资产按"账号权益制下发"交付行业用户。
- 关键实现：
  - **权益包**：订阅 / 按件、企业批量授权、吊销与离线宽限策略（口径见评审稿第 6 章）；
  - **共用下发管道**：与 C4 内测同一条管道，仅授权策略不同（内测名单 vs 权益包）——不为内测另造下发机制；
  - **支付对接**：桌面端只发起支付动作，支付真相与权益收口云端 OPC（既定分层）；
  - **正式分发 = 权益门卫 + 拉取式交付（2026-09-09 定稿）**：OPC 判定账号权益（已付费 / 套餐有效 / 额度余量 / 吊销）并发出"权益有效"状态（唯一真相）；Ti Work 云端管理端作为分发电枢，仅对权益有效账号放行"可用资产包清单"（版本 + 授权策略 + 下载凭证），账号吊销即清单即时失效；桌面按该账号登录拉取资产包 → 本地安装加载运行（离线宽限沿用权益包策略）。资产本体始终在 Ti Work 云，不因权益动作迁入 OPC；
  - **结算分成**：头部贡献者署名 + 分成/版税（评审稿第 6 章成立前提）。
- 首案取舍：不建真实计费；用"权益清单"模拟授权，验证管道与状态流转即可。

### C6 OPC 审核与运营后台（平台治理关卡）
**落点端**：审核操作与巡检 = OPC admin 后台（平台治理）；**资产本体不迁入 OPC**——试跑通过的 candidate 由 Ti Work 云端管理端提交，OPC 打审核通过戳后回写 Ti Work 云资产库标记正式。
- 职责：行业资产上架的最后一关 + 平台巡检。
- 关键实现：审核工作台（资产质量报告可视化：样本覆盖、修订链收敛、校验规则命中）、涉密巡检（引用清单扫描，对齐桌面脱敏红线）、发布审批、审计留痕。
- 首案取舍：人工审核 + 简单报告即可，巡检词表先内置通用规则。

### C7 横切基础服务
账号中心 / 审计日志 / 任务调度 / 站内通知（复用 Ti Mind / 平台既有横切服务，不新增自研）。

## 4. 版本与数据契约衔接（云端 ↔ 桌面）

| 契约 | 方向 | 最小字段（语义） | 对应 |
|---|---|---|---|
| 样本回传 | 桌面 → 云端 | 契约 schema（需求摘要 / 规范要素 / 修订链 / 脱敏引用） | 桌面 D1-D5 |
| 共创授权 | 云端 → 桌面 | 账号共创状态 / 吊销 / 离线宽限 | C1 ↔ 6.6.11-U |
| 权益判定 | OPC → Ti Work 云管理端 | 账号付费 / 套餐 / 额度余量 / 吊销（唯一真相，即放行依据） | C5 |
| 资产下发 | 云端 → 桌面 | 资产包 Schema（工序 + L1 + L2 + KB 清单）+ 版本 + 授权策略；**仅权益有效账号放行清单（含下载凭证）** | C4/C5 ↔ 桌面加载器 |
| 跑测反馈 | 桌面 → 云端 | 样例清单 / 版本 / 结论 / 问题 | C4 |

- 资产包 Schema 版本契约必须"单向兼容"：老桌面可读新资产，新 Schema 上线需版本协商（OPC 单一版本治理同步）。
- 正式下发动作形态 = **权益门卫 + 拉取式交付**：OPC 判定权益发状态 → Ti Work 云端管理端放行可用清单 → 桌面按账号拉取安装运行；资产本体不因权益动作迁入 OPC。
- 内测与正式的下发载荷同构，仅授权字段（名单 vs 权益）不同；内测 = 名单制放行（管理员指定账号），正式 = 权益制放行（OPC 判权益），共用同一下发管道与载荷。

## 5. 分期实施

**一期（首案最小闭环）**
- C1 手动开通/吊销 + 资质档案留痕；C2 样本库 v1；C3 人工起草初版规范 + 修订链统计辅助 + 打包器 v1；C4 状态机 + 手动名单 + 反馈回流；C6 人工审核；C5 权益清单模拟；C7 复用。
- 交付口径：一条业务线（首案交付物类型）从"共创账号回传 → 加工出 candidate → 管理员下发 → 验收账号本机试跑 → 反馈迭代 → 审核通过"全链路跑通。
- 载体口径：业务面（C1-C5 / C6 运营面）落地 **Ti Work 云端管理端**（暂名，与桌面账号同源）；OPC 侧先以"人工审核通过节点 + 权益清单模拟"最小介入，不铺平台功能；C3 能力调用 Ti Mind。

**二期（规模化）**
- C1 自动分层邀请与质量打分流水线；C3 常驻蒸馏 job + 模型化 L1/L2；C4 试跑记录自动聚合；C5 真实计费与分成；C6 自动巡检。

## 6. 治理与红线（云端侧）

- 只持脱敏契约样本，不持真实交付正文；密文存储 + 最小权限；删除权即时生效；
- 共创 Gate：非共创账号零样本入库（默认关闭是隐私与治理双防线）；
- 资产上架必须：candidate 经下发试跑反馈 → OPC 审核（含涉密巡检）→ 正式，缺一不可；
- 云端无执行、无沙箱——任何环节不得引入"云端跑用户真实任务"的实现（与执行位置定稿一致）；
- 审计：授权变更、下发名单变更、审核动作、版本状态流转全程留痕。
