# Ti 系列"工作方式蒸馏" 设计评审稿（已收敛为首个落地案例）

> 状态：评审稿（2026-09-09，第三次评审收敛：承载口径修正为 **Skill 规范资产承载 + 云端治理 + 桌面执行**；行业化仅为 OPC 审核售卖的额外通道。**共创口径补定（2026-09-09）**：蒸馏改为**共创两层模型**——L1 个人本地养成全员可用；L2 共创沉淀通道仅限云端定向开通的共创账号、默认关闭、开通后系统自动沉淀，不再"全员可上云共创"。**共创准入补定（2026-09-09）**：L2 共创账号准入 = **分层验证制**——共创者须专业且行业翘楚，但以可验证的专业性分层认定（执业资质 + L2 度量 + 修订链稀疏 + 同行背书）；共创是候选池非免检，商业化价值由资产验收决定）。

> 命名口径（已确认）：**Ti Mind = LingShu 中台**（统一智能体内核 / Digital Hub，口径见《Ti Work 企业日常办公平台规划》8.5.12.7）。**服务载体分层（2026-09-09 定稿，云端蒸馏链路侧）**：本文"云端业务承载"指 **Ti Work 配套云端管理端**——与 Ti Work 桌面**同账号同源**的产品 Web 云（暂名），承载共创运营 / 资产沉淀 / 加工业务 / 下发验证；Ti Mind 仅为**能力供给底座**（模型 / 蒸馏算法 / 知识抽取）；OPC 仅为**平台治理关卡**（商业化审核 / 支付与权益发令 / 不可变审计）。后文"云端"如无特指均按此分层理解。

## 1. 方向收敛（本次评审定稿）

1. **重放对用户无必要**：用户价值不在"把步骤重放一遍"，而在"拿到与他本人亲手交付一致的结果"。Agent 运行过程的事件序列**照常记录**（作为数据与审计留痕），但**不作为对用户的功能出口**，不提供"高频任务 / 流程步骤重放"入口。
2. **首个案例定义**：一家律师事务所、**非诉讼律师**日常办公内容。先跑通单一案例，验证"数据 → 智能体 → 交付一致"的完整闭环。
3. **成功标准**：智能体交付结果与**本人交付一致**（该所的交付质量基线），以此作为该智能体向行业开放商业化的前提。
4. **核心关注**：拿到这些数据（作业过程 + 交付物）之后，**如何沉淀为最终能交付准确结果的智能体**——本文第 5 章为该核心。
5. **承载与执行位置（本次定稿，修正为 Skill 承载 + 桌面执行）**：蒸馏产物 = **可执行的 Skill 规范资产**（L1 三件套 + L2 基线封装），云端只负责**存储 / 版本 / 审核 / 售卖**，**执行必须发生在桌面本地**——用户的办公目录与本地操作数据在自己电脑上，云端即便全权执行也拿不到真实的本地操作数据，桌面端是承载用户办公的执行面，不是把任务交给云端的"遥控器"。**不采用**"蒸馏产物收口为中台编排、由 LingShu 云端执行"的路线（那是强拧两套系统、风险虚高的来源）。Workflow / 云端编排仅作为后续后台自动化 / 跨设备 / 无人值守场景的独立演进出口。
6. **共创两层模型（2026-09-09 补定，修正"蒸馏全员开放"口径）**：按数据去向拆两层，避免"共创 = 人人可上云"稀释质量供给：
   - **L1 个人本地养成（全员默认可用）**：会话任务序列 / 意图 / 高频任务 / habit / 记忆等养成数据只落本地，人人可积累自己的工作方式（越用越准）——桌面核心价值 = 本地真实执行 + 数据主权；
   - **L2 共创沉淀通道（账号级 Gate，默认关闭）**：凡涉及交付物样本 / 脱敏快照 / 修订链登记回传的共创蒸馏，仅限**云端（Ti Work 配套云端管理端）定向开通的共创账号**；默认不开，开通后系统自动采集沉淀、无需用户手动上报；普通账号无自助开启入口；
   - **L2 共创准入 = 分层验证制（可验证的专业性，2026-09-09 补定）**：共创者须是"专业、行业翘楚"——但**以可验证的方式认定，而非只看头衔**：执业资质（必要项）+ 交付样本经 L2 基线度量达标 + 本人修订链稀疏（一次成型率高）+ 权威同行背书；分层邀请（资深级共创 / 骨干级共创候选）防供给枯竭；共创仅"进候选池"，**沉淀资产仍统一过验收**（稳定中上 + 方差收敛 + 执业复核点 + 脱敏 + OPC 审核）——商业化价值来自**验证过的资产**，不由共创者身份决定；
   - 行业商业化是"已验收共性规范经 OPC 审核上架"的**额外通道**，不排他，与 L1 不冲突：全员可养成各自习惯，共创上云由云端治理定向开放，从源头控样本质量。

## 2. 竞品基线：讯飞 Loomy「自我蒸馏」拆解（2026-09-09 二次调研）

> 事实修正：科大讯飞桌面应用 **Loomy**（AI 工作搭子，Windows/macOS）确实具备蒸馏能力——官方技能「自我蒸馏」。本条作为本稿第 5 章沉淀管线的重要参照。
> 同族定位（修正）：Loomy 属讯飞「Claw 全家桶」的桌面端执行形态；同族另有 AstronClaw（云端 Agent）、GlassClaw（AI 眼镜入口）、RobotClaw（机器人超脑）。桌面 Loomy 与云端 AstronClaw 是同一家族的两条执行形态，**不宜表述为"基于 AstronClaw 的壳"**——恰与本稿"桌面执行端 + 云端中台（Ti Mind）"的双形态架构同构。

**Loomy 蒸馏的实现方式：**

- **载体定位**：桌面端执行型 Agent，核心是"把复杂重复跨工具的工作流落到执行层"；授权工作目录内干活、本地资料库向量化（全程不上传）、可自配第三方模型 Key（仅本地使用）——隐私模型与本稿"执行端 + 授权"路线一致。官方宣传口径为"文件存你电脑里、只在你授权的文件夹里干活、不传云端"；模型支持星火/DeepSeek/通义/豆包/Kimi/MiniMax 等可切换，亦兼容自配端点（如 Ollama）。
- **蒸馏技能**：官方技能「自我蒸馏」：把"你自己"蒸馏成一个可运行的 AI Skill——解构聊天记录、日记、社交媒体和照片，生成带**人格模型 + 记忆模型**的数字分身；触发语含"创建数字分身 / 自我镜像 / 个人知识档案 / 把自己蒸馏成 skill"。
- **能力区分（防混淆）**：Loomy 的"像你"能力有两条独立线——① **Buddy 数字分身**：只上传一张照片 + 一段性格/工作风格文本描述，即生成外形与风格近似的分身（人格塑造，不读素材）；② **「自我蒸馏」**：真正解构聊天记录/日记/社媒/照片等素材，产出可运行 SKILL。本稿对标的是 ② 的"素材 → 可运行资产"语义，并补齐其未覆盖的交付质量层。
- **产物结构**：可运行的 Skill（SKILL.md 规范类文件，可安装复用）；人格模型 + 记忆模型对应开源 colleague.skill 的 Persona（五层：硬规则/身份认同/表达风格/决策模式/人际行为）+ Work 双模块语义。
- **生命周期**：创建 → **追加进化**（持续补素材）→ **对话纠正**（"他没这么写/这么说"即修订）→ **版本回滚**——把"蒸馏是一次性快照"升级为可持续维护资产，是行业化上架前必须具备的可迭代性。近期版本另上线**技能自进化**：从日常对话中自动学习并沉淀新技能，设「已学技能」管理入口供查看/调整学习成果——不依赖显式蒸馏动作的后台持续沉淀，对应本稿"过程级留痕"思路；但其收敛产物仍是技能/偏好，**不是**可校验的交付规范。
- **结果侧补强（Skill 生产实为四通道）**：①「从结果反推」——给一份满意交付物（PDF 等）反推结构模块/数据来源/流程节点并参数化沉淀为 Skill；② record-and-replay/录制操作——录制操作过程自动提取变量与模板生成 Skill；③ 访谈式——对话问答 5~7 轮自动产出 SKILL.md（一键保存至本地 `loomy-skills/` 目录）；④ 手动——自带 SKILL.md + skill.yaml 拖入「Skill 管理」加载。共性：**把"一次成品/一次操作"压缩为可复用资产**（即本稿 L1 的输入形态）；缺口：**不校验"成品质量是否达标"**，沉淀进去的规范质量由用户素材质量决定。
- **护栏**：官方定位是蒸馏"自己"（自我镜像），不鼓励蒸馏他人；技能具备 allow/ask/forbid 三级权限；目录级授权 + 本地优先。执行方式（用什么工具/何时执行）允许用户手动选择调整，Loomy 会把用户的选择与修改吸收为个性化反馈——与本稿"本人怎么改 = 不一致信号"的纠偏逻辑同构，只是它收敛为偏好、而非交付校验。

**对本稿的启示（差距即机会）：**

1. Loomy/开源生态的蒸馏产出停留在"人格/记忆/过程层"，要到交付文档仍需叠加公文写作、Word 等输出技能——**行业交付质量没有收口进蒸馏资产**；本稿 L1 把"模板骨架 + 生成约束 + 校验规则"纳入蒸馏产物，正好补齐该层。
2. "追加进化 / 对话纠正 / 版本回滚"证明蒸馏资产必须生命周期化，与行业底座在 OPC 单一版本 + 审核更新的资产治理吻合。
3. Loomy 只做"自我"授权语义；我们的商业场景是"蒸馏资深律师的交付能力并向行业付费开放"——授权与权益复杂度更高，须落到统一账号授权体系（与 6.6.11-U 同批）。
4. **三条"像你"线均未触及"本人怎么改稿"**：Buddy（人设）、自我蒸馏（素材 → 人格/记忆）、技能自进化（对话 → 偏好/技能）都缺最硬的质量信号——**本人对初稿的每一处修改**。该"修改链"恰是本稿 L2 独有的纠偏数据源（见第 4 章与 Step 3），是竞品与开源生态都尚未收口的机会点。

## 3. 首个案例的界定（待与该所落地确认）

- 业务切面：**非诉讼（non-contentious）日常办公**，候选范围（以该所真实业务为准）：
  - 合同审查与修改（含审查要点清单、批注稿、修改说明）；
  - 法律研究与备忘录（检索报告、issue memo）；
  - 法律意见书 / 律师函 / 尽调报告等文件的初稿与交付稿；
  - 日常咨询答复、会议纪要后的待办与跟进文书。
- 作业方式：非诉律师在桌面端完成（文档编辑、检索、审阅、交付），过程事件与交付物可采集。
- 数据授权：与该所及当事人确认**作业数据脱敏 + 授权蒸馏**（涉及客户机密的文档仅取结构/措辞/规范要素，不沉淀正文）。

## 5. 核心：从数据到"能交付准确结果的智能体"（沉淀管线）

目标产物不是"像本人风格"的描述，而是**能在真实作业里产出与本人交付一致结果的智能体**。管线分五步：

### Step 1 素材归一化与样本对齐
把三类素材对齐成 **(需求输入 → 交付物)** 的可学习样本，并补上下文：
- 需求输入：会话中的任务要求、客户约束、事实材料；
- 作业上下文：引用的法规/案例/模板、检索材料；
- 交付物：本人最终交付文档 + 过程中的修改链（本人对初稿的每处修改 = 最直接的质量信号）。

### Step 2 蒸馏 L1 结果生产规范
从样本蒸馏出**可被 Agent 执行**的规范资产（非文风描述），法律非诉业务至少含：
1. **内容与论证逻辑**：各类文书（审查意见/备忘录/法律意见/律师函）的固定结构、必含章节与论证顺序；
2. **格式与版式硬约定**：国标公文/律所模板/所内风格，排版要素；
3. **措辞与引用体系**：法言法语、术语一致性、法条/案例引用格式、禁语检查；
4. **生成规则**：什么输入产出什么文档类型、从哪些来源取引用、质量到何种程度才算可交付。

### Step 3 建立 L2 交付一致性基线（"与本人交付一致"的度量）
- **机器可执行校验**：格式合规、结构完整、术语一致、引用格式、禁语检查；
- **基准比对**：同主题下与本人历史交付物做结构覆盖与措辞贴近比对（原文不沉淀，只保留可比对基准）；
- **执业复核点**：法律结论、事实认定、风险判断等承担执业责任的节点保留给本人/执业者确认——**行业责任边界，不是产品缺陷**。

### Step 4 沉淀为可执行 Skill 规范资产（承载定稿：云端治理 + 桌面执行）
蒸馏产物 = **Skill 规范资产包**：云端单一版本 + 审核治理 + 可售卖；桌面经授权**加载到本地执行引擎运行**，数据不出授权目录：
- `Skill（主体）` = 该业务线"工序指令 + L1 生成约束 + L2 校验规则"的可执行封装（读需求 → 检索 → 起草 → 自查 → 标注复核点 → 输出交付稿），由桌面本地 Agent 运行时加载执行；
- `KB` = 空白范本 / 律所模板 / 法规案例引用源（授权与脱敏后入库，随 Skill 下发引用）；
- 运行即"真实做事"，事件序列照常经 P1 链路留痕（审计与调优数据），不对用户暴露重放；
- **执行位置原则（定稿）**：桌面端是用户办公的执行承载面，任务执行不交给云端；Workflow / 云端编排仅作为后续后台自动化 / 跨设备 / 无人值守场景的独立演进出口，不是行业首案的运行方式。
- **预沉淀版本（candidate vN，2026-09-09 定稿）**：云端只负责"加工出 Skill 资产版本 + 治理"，不承担执行；每一版蒸馏产物先以**预沉淀版本**形态存在，供"管理员下发 → 指定账号真机试跑"验证（见 Step 5）——预沉淀版之于正式版，即测试环境之于生产环境。

### Step 5 验证与调优循环（定稿 2026-09-09）
- **验证动作 = 预沉淀版本下发试跑**：candidate vN 由**管理员下发**到指定账号——可共创者本人、可**中立验收账号**、可种子体验账号，下发名单即"谁能体验 / 谁先验证"的控制面；被下发账号在本机**真机接入试跑**（像测试环境跑验收用例），产出与本人预期 / 验收基线比对；云端不建沙箱、不做执行；
- **反馈回流迭代**：跑测结果与问题反馈回流云端 → 管理员决策：迭代 vN+1 再下发，或判定通过 → 转正式（OPC 审核上架）；
- **影子模式（收敛期自动辅助，不打扰）**：共创者本人作业期的 L2 收敛仍可走后台离线比对（本人交付 vs Skill 资产在桌面沙箱试运行产出），统计人工改动量、结构覆盖度、格式/引用合规，不打扰不拦截；
- 收敛达标后，该 Skill 资产转为桌面**按需加载的正式能力**（本人可用 → 所内授权 → 行业化候选，分级放行判据见第 8 章）；
- 记录每一次本人修改 → 反哺 L1/L2 → 版本审核后更新云端 Skill 资产（与 OPC 单一版本治理一致）；
- 迭代目标：N 类交付物的人工改动量收敛到设定阈值，达到"与本人交付一致"验收线后才进入商业化。

## 6. 商业化路径（单案例 → 行业开放）

1. 首个智能体以该案例所的真实水准为基线完成验收（第 5 章 Step 5）；
2. **剥离所内专有信息**，保留行业共性规范 → 行业底座（复用行为资产方案 P1-C 工序：脱敏 → 共性提炼 → 封装 → OPC 审核 → 上架）；
3. 面向行业开放付费：同行业用户付费获得**同样的交付结果**（B 端订阅或按交付件计费，计费口径待商业确认）；
4. 资产分层不变：个人/所内增量(本地与授权) + 行业底座(OPC 单一版本售卖)。
5. **对标 LawClaw（劳有钳，JurisMind 法义经纬）的分发形态结论（2026-09-09）**——形态上吸收、机制上修正：
   - **吸收（前端形态）**：技能商店式浏览/排序/分类 + "一键安装到本地执行" + 本地运行、数据不出授权目录——验证了"Skill 生态库 + 桌面执行"是被市场接受的法律 AI 桌面化形态，与本文承载口径同构；
   - **不照抄"付费下载即拥有"**：LawClaw 目前 Skills 全免费 + 赠算力积分（走"数字普惠"换算力消耗，未做资产售卖）——反证纯 Skill 文件在行业里卖不动，可收费的是"能交付与资深律师一致结果"的行业规范资产（本稿差异点）；
   - **分发 = 账号权益制下发**：桌面端只发起支付动作，支付真相与权益收口云端 OPC；下发的是**绑定账号、可更新/吊销的可运行副本**（订阅/按件授权随账号同步），非文件买卖——支持企业批量授权与多人复用，也与既定"支付真相收口云端"分层一致；
   - **质量漏斗差异**：LawClaw 共创社区"人人可上传分享"（无交付质量把关）；本稿对"上云共创"本身设**账号级 Gate**（L2 共创通道仅云端定向开通账号可用、默认关闭，L1 全员养成只落本地，见第 1 章第 6 条），行业上架再叠加验收 + 脱敏 + OPC 审核——比 LawClaw 多两道质量闸（共创 Gate + 上架审核）；
   - **共创准入 = 分层验证制（2026-09-09 补定，细于第 1 章第 6 条）**：账号"定向开通"是**候选池入口而非身份背书**——共创者需专业且属行业翘楚，但以可验证的专业性分层认定（执业资质 / L2 度量 / 修订链稀疏 / 同行背书）；行业资产能否商业化，最终由**资产验收**说了算，不由共创者头衔说了算；
6. **商业化质量门槛与双轨逻辑（2026-09-09 确认）**：
   - **门槛定义**：可商业化的行业资产必须**稳定达到行业中上**（L2 基线收敛、方差收敛）**且执业复核点覆盖**——不是"一次性超越 80% 从业者"；法律行业买的是稳定的可交付，偶发惊艳/偶发失准的资产无人敢用。买方参照系分层：下沉市场卖"稳定可用的中上模板"，上层市场卖"资深交付一致 + 权威背书"；
   - **双轨不冲突**：个人蒸馏 L1（全员本地养成，数据不出本机）与行业商业化（共创 Gate + 验收 + 脱敏 + 审核上架）互为"漏斗 + 滋养"——行业化只消费共创账号经授权回流的样本，不触碰任何人的个人本地资产；
   - **头部创造者回馈（成立前提）**：行业资产必须为头部贡献者设**署名 + 分成/版税**（规范制定者署名、版本更新分成），否则最佳实践供应枯竭、行业资产永远上不了质量门槛；出售的是"技能资产"而非其客户关系与执业身份，创造者本人仍是背书人与受益者。
7. **预沉淀内测与正式下发的同一通道（2026-09-09 定稿）**：商业化正式分发 = 账号权益制下发；预沉淀验证/内测走**同一条下发管道、不同授权策略**——内测名单（管理员配置：共创者本人 / 中立验收账号 / 种子体验账号）vs 正式权益包（绑定账号、可更新/吊销）——不为内测另造一套下发机制；预沉淀版本经"下发试跑 + 反馈迭代"通过后，才转入正式权益制下发。
