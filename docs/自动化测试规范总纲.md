# 自动化测试规范总纲（通用版）

> 适用端：Web / 小程序 / H5 / App
> 适用阶段：需求评审、开发自测、提测验收、回归测试、发布前冒烟
> 使用方式：按项目裁剪（只保留适用端的条目），编号全局唯一，便于追踪与微调。

## 标签规则（每条编号后标注，裁剪与分级直接查表）

| 标签 | 含义 |
|------|------|
| `[全端]` | Web / 小程序 / H5 / App 全部适用 |
| `[Web]` | 仅 Web 管理后台 / PC 端适用 |
| `[小程序]` | 仅微信小程序适用 |
| `[H5]` | 仅移动端 H5 适用 |
| `[App]` | 仅原生 App 适用 |
| `[移动端]` | 小程序 / H5 / App 适用（不含 Web） |
| `[P0]` | 阻断发布，必须执行（自动化或人工必测） |
| `[P1]` | 必须修复，正常发布前执行 |
| `[P2]` | 可迭代，体验类/合规类，不设发布硬门槛 |

> 裁剪动作：先按"端"删掉不适用的行，再按"P级"决定执行深度（P0 全做、P1 抽查、P2 视资源）。
> 执行手段映射见《自动化测试规范-执行优先级表.md》。

# 第一部分 功能流程测试规范

> 目标：验证"业务能不能走通"，覆盖正向、逆向、异常、边界、权限、并发等场景。

| 编号 | 规则 |

# 第二部分 交互规范测试规范

> 目标：验证"UI 交互是否符合规范"，重点是对"控件选型是否正确、交互是否可用"。
> 执行建议：控件选型（2.1）与表单校验（2.2）优先走 **AI 静态代码审查**（低本高效）；触控/键盘/权限等运行时行为走 UI 自动化抽查或人工抽测。

## 2.1 控件选型规范（该用什么控件就用什么控件）

> 核心原则：**类型化输入必须用类型化控件，禁止用自由文本替代。**

### 2.1.1 输入类

> 执行原则：**ROI 分层**——数据走接口测试、交互走静态审查、流程只跑 P0 冒烟。详见《自动化测试规范-执行优先级表.md》。

| 检查类型 | 手段 | 成本 | 频率 |

| 数据正确性 | 接口/单元测试（断言计算与边界） | 低中 | 每次 push |
| 数据安全 | 安全扫描 + 接口审计 | 中 | 定期 + 发版 |

## 优先级建议

- **P2（可迭代）**：体验细节、兼容性、无障碍
