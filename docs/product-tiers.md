# Ti Work 产品形态分层与分批实施路线

> 状态：方案文档（2026-08-13 用户确认，作为 [architecture.md](./architecture.md) 的产品演进章节）
> 来源：用户提供的产品分层图 + 既有三形态授权模型（development-guide v7 §5.2）
> 原则：**装完即用**——安装包内置 Hermes 引擎并自启（所有版本共用同一底座），用户唯一必需操作是首次填入一次 API Key（企业版连 Key 都不用填）。

---

## 一、产品形态总览

```
装完即用：安装包内置 Hermes 引擎 + 自启（所有版本共用）
 │
 ├─ 单机版（匿名/软登录）
 │   本地全功能（聊天/Agent/记忆/技能/多智能体）
 │   用户唯一操作：首次填一次 API Key
 │   登录（可选）→ 账号中心：订阅升级 / 云同步 / 遥测
 │
 ├─ 单机版（付费订阅：标准/专业）
 │   登录后按 featureSet 解锁高级能力，到期自动降级
 │
 └─ 企业版（Ti-Work-Web 分配账号登录）
     企业统一下发配置：模型白名单 / API Key 企业统一管理
     用户连 API Key 都不用填 → 真正的零配置
     功能裁剪 + 审计 + 席位管理 + 离线补报（已实现）
```

### 1.1 三形态对比

| 维度 | 单机版（匿名/软登录） | 单机版（付费订阅） | 企业版（中枢分配） |
|---|---|---|---|
| 登录 | 可选（软登录，不登录零限制） | 登录后按 featureSet 解锁 | Ti-Work-Web 分配账号登录 |
| API Key | 首次填一次（唯一必需操作） | 首次填一次 | **企业统一下发，用户零配置** |
| 模型 | 本地自由选择 | 本地自由选择 | 企业模型白名单 |
| 高级能力 | 本地全功能 | 标准/专业 featureSet 解锁，到期自动降级 | 企业统一裁剪 |
| 账号中心 | 订阅升级/云同步/遥测 | 订阅管理 | 企业席位/审计（已实现 G8） |
| 底座 | 内置 Hermes 引擎 + 自启（共用） | 同左 | 同左 |

### 1.2 底座（所有版本共用）

- **安装包内置 Hermes 引擎运行时**（Python + hermes-agent），安装即自带执行引擎，不再要求用户另行安装 Hermes。
- **首启自动安装/自启**：当前落地架构中，安装包会内置 bootstrap 安装器与 Hermes 源码快照；**真正的 Hermes 安装与网关启动发生在用户第一次打开 Ti Work 时**，而不是 NSIS 安装向导阶段。对用户的目标体验仍然是"安装完第一次打开即可用"。
- **自启**：主进程启动时自动 spawn 引擎网关（127.0.0.1:8642）→ 健康检查 → 崩溃自动拉起；网关对用户完全隐形。
- 所有版本共用同一安装包与底座代码，差异仅在"登录态 + 授权 featureSet"。

## 二、批次实施规划（依赖有序）

### 批次 0：引擎可用性兜底（先行，独立）
- 网关离线时 UI 不误报：模型下拉提示条、fallback 模型标注"需启动网关"、模型显示名更新（DeepSeek 等新模型）。
- 直连降级：`openaiChat` 支持自定义 baseUrl/apiKey，网关离线时 portable 分支直连所选 provider 的 OpenAI 兼容 API。

### 批次 1：引擎内置 + 自启（装完即用的核心）
- NSIS 安装包内置 Hermes 运行时（Python 环境 + hermes-agent 依赖）。
- 主进程（`electron/main.ts`）首次启动：spawn 引擎 → 健康检查（8642 端口）→ 崩溃自愈。
- 首启引导：检测 `~/.hermes/.env` 无 Key → 弹出"首次配置 API Key"引导页（唯一必需操作）。
- **协作前置要求**：本批次未打通前，禁止把移动端连接、外网访问、Tailscale/LAN 访问作为对外主卖点或首屏提示。

### 批次 2：单机版软登录 + 账号中心
- 软登录：不登录不限制任何本地功能；登录为可选。
- 账号中心 UI：订阅升级（featureSet 预览）/ 云同步开关 / 遥测开关。
- 复用 `hub-client`（`hubLoginGate` 仅 hub 配置时触发，单机版永远放行）。

### 批次 3：付费订阅（标准/专业）解锁与降级
- 登录后按 featureSet 解锁高级能力（集成/编排/多智能体等，见 development-guide §6.4 裁剪矩阵）。
- 到期自动降级：featureSet 过期 → UI 回退免费版呈现 + 提示续费。
- 门禁实现：`lib/feature-set.ts` 定义枚举 + `canUse(feature)`（商业授权 && 技术能力双轨判断，两类失败分别提示）。

### 批次 4：企业版收口（G8 已实现部分）
- 企业统一下发配置：模型白名单 / API Key 统一管理（用户在设置页仅可见白名单内模型，无需填 Key）。
- 功能裁剪 + 审计 + 席位管理 + 离线补报：**已实现**（G7/G8），本批次做 UI 收口与白名单模型选择器接入。

### 批次依赖关系

```
批次 0（引擎可用性兜底）
   ↓
批次 1（引擎内置+自启）── 装完即用闭环
   ↓
批次 2（软登录+账号中心）
   ↓
批次 3（订阅解锁/降级）── 依赖批次 2 的登录态
   ↓
批次 4（企业版 UI 收口）── 依赖 G7/G8 中枢（已完成）
```

> 说明：批次 0 先行是因为它解决当前用户可感知的"配了 Key 发不出"bug 且独立可交付；批次 2 必须在批次 1 之后（登录能力依赖底座可用）。

### 2.1 协作准入门槛（首装优先于一切）

项目进入多人协作后，必须明确一个产品准入顺序：

1. **先打通桌面端首装 Hermes**
2. 再做账号中心 / 订阅解锁
3. 最后再恢复移动端连接与跨端访问包装

原因不是技术洁癖，而是产品路径约束：

- 首装链路是所有用户的第一体验，失败一次就会直接怀疑产品可靠性。
- 移动端连接天然额外引入 `Tailscale / 局域网 / 手机浏览器访问` 等理解成本。
- 在桌面端首装尚未稳定前继续暴露移动端入口，只会让用户形成"这个产品一上来就要做很多配置"的负面心智。

**定稿：首装链路未通过前，移动端连接能力属于冻结范围，不进入首屏、不进入 onboarding 主路径、不作为市场话术。**

### 2.2 移动端连接的生产级收口策略

| 决策项 | 结论 |
|---|---|
| 产品定位 | 移动端连接是**二级能力**，不是首装主路径 |
| 当前处理 | 在桌面端首装 Harness 全绿前，移动端入口应默认隐藏或仅保留给开发/评审开关 |
| 恢复条件 | 仅当桌面端实现"安装包打开 → 自动安装/启动 Hermes → 可稳定发第一条消息"后，才允许重新开放 |
| 文案策略 | 恢复后也不能写成"几步即可将手机连接到这台 Ti Work 实例"的首屏提示，而应降级到设置页/帮助页里的可选能力 |
| 技术前置 | 移动端说明必须明确依赖：同网段访问 / Tailscale / 企业中枢转发，三选一；禁止让用户自行猜测 |

**推荐落地：**

- 当前版本：`MobilePromptTrigger` / `MobileSetupModal` 从默认用户路径移除，保留开发开关。
- 首装稳定版：移动端入口放到 `设置 > 高级能力 > 移动端访问`，明确标注"可选能力"。
- 企业版后续：若中枢可提供统一入口，再评估是否把移动端访问升级成正式卖点；在此之前，不占用首屏心智。

## 三、关键决策与边界

| 决策点 | 结论 |
|---|---|
| 引擎形态 | 安装包内置 Hermes 运行时 + 主进程 spawn/自愈；不再要求用户手动安装 Hermes |
| 软登录 | 单机版登录可选，不登录零限制（传统企业用户零门槛）；登录仅开启账号中心（订阅/云同步/遥测） |
| 零配置 | 企业版由中枢统一下发模型白名单与 API Key，用户端零配置 |
| 直连降级 | 网关离线时降级直连所选 provider 的 OpenAI 兼容 API（仅 portable 分支），避免"有模型发不出" |
| 首装优先级 | Hermes 首装/自启稳定性高于一切新增入口；未通过前，移动端连接默认隐藏或冻结 |
| 授权边界 | 复用 development-guide §5.2 三形态授权矩阵 + §6.4 功能裁剪矩阵；MIT 版权段与来源声明必须保留 |
